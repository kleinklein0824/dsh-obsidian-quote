# 连接与面板

1. 根据当前 SKILL.md 的实际文件位置确定插件根目录，运行根目录下的 `harness-skill/scripts/setup.mjs`（Node.js）。使用绝对路径，适配带空格的目录；无需复制或展示令牌。
2. 按脚本的真实状态继续：`ready` 时报告已登记库数、笔记数与服务版本；缺少配置时让用户到 **Obsidian → 设置 → 第三方插件 → Obsidian Quote** 登记知识库并点击“写入接入配置”。离线与鉴权错误按实际结果解释。
3. 用户要求在 Codex 内显示或打开面板时，若当前会话有 `visualize` 能力，按 [references/codex-panel.md](references/codex-panel.md) 显示可操作的对话内检索入口。按钮请求 Codex 在后续回复调用 MCP，不是持续连接的侧栏或已验证的原生弹窗。客户端无此能力时，提供文本检索；用户明确要求浏览器时才为上述命令加 `--open`。
4. 调用可用的 `kb_vaults` 验证当前会话是否有工具。脚本连接正常但工具缺失或启动握手失败时，指出 Codex 加载层问题，检查客户端插件版本至少 0.1.2；通过市场更新该插件后重新加载会话。旧 0.1.0/0.1.1 的路径占位符在旧清单方式中可能未展开。

知识库添加、删除、包含/排除目录和服务设置位于 Obsidian 的插件面板。沿用现有本机连接与知识库配置，连接已正常时不重置令牌或重写接入文件；其他客户端的面板与安装保持原样。诊断只读服务状态与登记信息，检索用户笔记按其任务范围进行。完成标准：报告实际连接和当前会话工具可用性，显示宿主支持的入口，区分已验证与尚未验证的部分。
